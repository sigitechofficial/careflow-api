## Things worth knowing

- **No database migrations** in any of the above.
- **New endpoint:** `GET /policies/audience-roles` returns `{ id, name, staff }`. Policy audience `ROLE` rows point at `identity.Role` (sign-in roles), not the employee role lookup. To target the role on an employee's record, use Job titles.
- **Survey reminder links** use `ADMIN_APP_URL` on the API. If it isn't set, they fall back to the request's origin. Please make sure `ADMIN_APP_URL` is set on live.
- **Emails can get stuck.** `sendViaAcs` waits for Azure ACS (`pollUntilDone`) with no time limit. If ACS hangs, nothing is written to `MessageDeliveryLog`, so the email looks "sent" but never arrives. This happened with an Independent reviewer invite. Workaround: use "Forgot password". A proper fix (a timeout that logs it as FAILED) is still to do.
- **Two care-plan tests fail on `main`** (`CarePathwayFormRenderer.hybrid.test.tsx`). They failed before any of my changes, so they need a look from whoever owns that area.
- **Running admin tests on Node 26** needs `NODE_OPTIONS=--no-experimental-webstorage`, otherwise jsdom's localStorage breaks.
